# 会议智能任务管理系统使用手册

## 1. 系统入口

系统监听 `18098` 端口。

- 服务器本机访问：<http://127.0.0.1:18098/>
- 内网访问：<http://192.168.30.216/meeting/>
- 服务检查：<http://127.0.0.1:18098/health>

当前系统未启用账号登录和角色鉴权。请仅在受信任的内网环境使用，并根据岗位约定操作管理员功能。

## 2. 首页功能

打开系统后，顶部显示当前任务数量和服务状态，主要页面包括：

- **任务清单**：查看、搜索和筛选全部任务。
- **部门视图**：按部门查看任务，便于会议跟进。
- **会议信息**：查看当前会议的日期、类型、参会人员和领导要求。
- **导入会议**：上传会议材料并自动提取任务。
- **人工复核**：确认系统无法完全确定的任务候选。
- **操作记录**：查看新增、更新、重复和失败记录及原文证据。
- **部门工作台**：进入各部门的待办页面。
- **组织机构**：查看部门名称、简称和待办数量。

顶部的会议下拉框可以切换会议。选择“全部会议”可查看所有会议任务。

## 3. 导入会议材料

1. 打开 **导入会议**。
2. 选择会议文件，支持 `.pdf` 和 `.docx`，单个文件不超过 30 MB。
3. 填写会议题目、日期、时间、会议类型、参会人员和领导要求。
4. 点击 **开始自动处理**。
5. 等待处理进度完成。系统会依次执行材料解析、任务分类和数据库更新。
6. 完成后打开 **任务清单**，点击 **刷新任务** 查看结果。

会议日期必须填写，格式为 `YYYY-MM-DD`。同一时间只能处理一个会议导入任务；如提示已有任务运行，请等待当前任务结束。

处理完成后可能出现以下结果：

- **已完成**：全部处理成功。
- **完成但有失败项**：部分任务成功，需到 **人工复核** 或 **操作记录** 检查。
- **运行失败**：本次导入未完成，先查看错误提示和服务日志。

## 4. 人工复核

低置信度或信息不完整的候选会出现在 **人工复核** 页面。

1. 展开候选记录，先阅读“复核原因”和原文证据。
2. 展开 **处理表单**，检查任务标题、负责人、期限、部门、项目、优先级和状态。
3. 在“处理方式 / 目标任务”中选择：
   - **新建独立任务**：会议提出了新的任务。
   - **更新已有任务**：会议是在跟进已有任务。
4. 需要拆成多个业务子目标时，点击 **添加子任务表单**。
5. 可先点击 **保存全部表单**，确认无误后点击 **确认并执行**。
6. 不属于任务或确认不应入库时，点击 **拒绝整条记录**。

更新已有任务时，原任务说明和原文证据会保留；新填写的说明会作为进展追加到历史中。

## 5. 查看和维护任务

### 查看任务

在任务清单中可以按以下条件筛选：

- 任务标题、部门、项目或责任人；
- 状态：待执行、进行中、受阻、已完成、已取消；
- 部门和项目；
- 具体会议。

点击任务标题可查看任务说明、来源会议、原文证据、变更历史和历史发布记录。

### 管理员修改任务

管理员可在任务清单中点击 **修改**，编辑部门、项目、负责人、期限、优先级、状态和任务说明。来源会议和原文证据属于历史依据，不能通过人工修改覆盖。

点击 **人工新增任务** 可创建独立任务。新增任务必须填写任务标题和对应的原文证据；如任务来自会议，也可以选择归属会议。

点击 **删除** 时系统执行的是软删除：任务默认从清单隐藏，原文证据和变更历史仍然保留。勾选 **含软删除** 可以查看这类任务。

## 6. 部门工作台

1. 打开 **部门工作台**。
2. 选择对应部门，点击 **进入部门工作台**。
3. 在 **待办任务** 中查看本部门的待执行、进行中和受阻任务。
4. 点击 **处理任务**，选择处理后状态并填写本次进展说明。
5. 点击 **保存处理结果**。

任务标记为 **已完成** 后，会自动从该部门的待办清单中移出，但仍可在管理员任务清单和历史记录中查询。

如果提示版本已变化，请先刷新任务，再重新提交，避免覆盖他人的最新进展。

## 7. 训练样本和操作记录

- **操作记录** 会保留任务新增、更新、软删除、重复和失败结果，并显示对应原文证据。
- 在任务清单点击 **导出训练样本**，可下载包含证据和标签的压缩包。只有原文证据达到系统要求的任务才会被导出。

## 8. 常见问题

### 页面打不开

先确认服务是否运行：

```bash
curl -fsS http://127.0.0.1:18098/health
```

正常返回类似：

```json
{"status":"ok","database":"ready"}
```

如服务未运行，由管理员执行：

```bash
sudo systemctl status meeting-taskmanager.service
sudo systemctl restart meeting-taskmanager.service
sudo journalctl -u meeting-taskmanager.service -n 50 --no-pager
```

### 内网地址打不开，但本机正常

检查 Nginx 的 `/meeting/` 转发和内网地址 `192.168.30.216`，并确认客户端与服务器处于同一内网。不要直接把 `127.0.0.1:18098` 当作其他电脑的访问地址。

### 导入一直没有完成

不要重复点击提交。先查看导入页面的运行状态，再检查服务日志；确认上一次运行结束后再重新导入。

### 任务状态更新失败

先刷新任务详情再提交。若任务已被其他人更新，系统会拒绝旧版本提交，以保留最新进展。

## 9. 管理员注意事项

- 修改代码或数据库前，先停止 `meeting-taskmanager.service`，完成后再启动。
- 不要直接删除 SQLite 数据库；任务历史、操作记录和原文证据都保存在其中。
- 服务配置文件为 `/home/yty-s/meeting-m2-work/M6_TaskManager_Demo/deploy/service.env`，其中可能包含部署参数，不要公开其内容。
