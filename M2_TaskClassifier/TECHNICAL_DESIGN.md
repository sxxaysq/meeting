# M2 提示词基线技术设计

## 目标与非目标

当前目标是在没有片段级金标样本时，先闭合 `M1 clean_segments.json → M2 七分类 → 高召回路由 → 审计/人工复核`。它用于形成零样本基线、验证标签协议并积累人工修订样本。当前不训练 Encoder 或 LoRA，不生成 M6 完整待办，不对人员、设备或时间做标准化，也不声称达到候选召回率或 Macro-F1 门槛。

## 输入契约

每条输入来自 M1，强制要求 `meeting_title`、`segment_id`、`speaker_id`、`timestamp`、`raw_text`、`clean_text`、`quality_flags` 和 `uncertainties`。当前片段使用 `clean_text`，`raw_text` 作为回溯证据；上下文只取同一 `meeting_title` 前后各一条，防止跨会议串扰。M1 未提供的日期和会议类型显式写为 `UNKNOWN`。

## 推理与防护

1. XML 定界并转义全部会议文本，提示词声明其只是待分析数据；
2. 温度固定为 0，要求短 JSON，不输出思维过程；当前兼容服务仍会把内部思考计入 completion token，因此给出 4096 的生成预算以避免 JSON 被 512/2048 token 上限截断；
3. JSON Schema 固定七类、事件提示、路由、信号、证据和歧义字段；
4. 确定性检查标签代码映射、`segment_id`、主辅标签和 evidence 字符切片；模型若沿用 M1 的 `text/reason` 歧义字段，只做无损的 `field/description` 归一化；证据区间只在原文唯一精确匹配或仅空白折叠后唯一匹配时恢复，并在审计中记录；
5. 首次无效时只请求一次格式/证据修复；再次失败则不伪造分类，写入 `m2_review_queue.json`；
6. 后置弱规则只把疑似候选提升到 `EXTRACT/HUMAN_REVIEW`，从不直接确认正式任务。

## 错误与降级

- M1 契约缺失、重复 `segment_id` 或空 `clean_text`：批次启动前失败；
- API/网络错误：由 SDK 做有限重试，未恢复则批次失败，不吞掉异常；
- 响应 JSON、Schema、枚举、证据或 ID 无效：一次修复；
- 修复仍失败：保留两次模型响应到审计，原片段进入人工复核队列，进程退出码为 2；
- 安全关键词或弱任务信号被模型路由为丢弃：只提升到人工复核或抽取，保留覆盖原因。

## 测试与当前完成判据

自动化测试覆盖定界符注入、缺失元数据、证据精确切片、候选不可丢弃、安全强制复核、一次修复、跨会议上下文隔离和 M1→M2 文件级 smoke test。当前模块只有在目标环境中测试通过、实际 M1 样例可运行并生成三类输出时才标为“可运行”。模型质量必须在按会议日期/矿区隔离的金标集上另行评测。

当前实际 M1 中存在少量单段包含多类汇报和安排的超长话轮。M2 仍保留主/辅标签并用弱规则提升候选路由，但这不是理想的原子分类输入；后续应优先回到 M1 改进语义切分，而不是让 M2 用更长上下文掩盖上游问题。

## 后续替换路径

积累约 2,000～5,000 个复核片段后，冻结标签规范并建立零样本/少样本基线；再训练轻量中文 Encoder，按候选召回率、Macro-F1、困难负例误报、延迟和成本与本提示词方案对照。达到门槛后，Encoder 接管高频分类，提示词模型仅用于灰区二次判断或教师标注。
